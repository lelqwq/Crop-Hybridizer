# 教程布局的盘点、路线预演与工位核对

适用于 GTNH 2.8.4 旧 IC2，以及已安装 `crop_helper` 的服务器。本阶段只读取上方容器和运行时作物目录，输出候选路线，不调用机器人移动、转向、种植、收获或物品转移操作。

## 布局约定

沿用[使用 OC 机器人进行 IC 杂交自动化教程](https://gtnh.huijiwiki.com/wiki/%E4%BD%BF%E7%94%A8OC%E6%9C%BA%E5%99%A8%E4%BA%BA%E8%BF%9B%E8%A1%8CIC%E6%9D%82%E4%BA%A4%E8%87%AA%E5%8A%A8%E5%8C%96)的布局，方向以机器人为准：

```text
前方： [左亲本] [中央杂交架] [右亲本]
                   ↑ 朝向
                 [机器人]
后方：           [充电器]
```

- 机器人保持中央待机位，面向中央杂交架。
- 正上方容器继续存储种子；本阶段将它同时作为初始种子盘点入口。
- 正下方作物架补给、左右侧下方除草剂补给保持原位。
- 机器人内部 1、15、16 号功能槽及现有农场均无需调整。

新程序只统计上方容器，左右活体和机器人背包不计作可取用种子。运行前结束旧脚本的杂交循环，避免盘点过程中库存发生变化。

## 安装与运行

将文件复制到 OC 硬盘并保留以下结构。盘点/预演兼容旧辅助模组；现场检查需要服务器安装 `crop_helper` 0.2.0：

```text
/home/crop_plan.lua          ← oc/crop_plan.lua
/home/lib/crop_preview.lua   ← oc/lib/crop_preview.lua
/home/lib/crop_site.lua      ← oc/lib/crop_site.lua
```

盘点种子箱：

```sh
crop_plan.lua inventory
```

指定目标品种及箱内期望总数，进行路线预演：

```sh
crop_plan.lua plan IC2:coffee 2
```

不带参数运行 `crop_plan.lua`，会询问目标 ID 与数量。品种 ID 区分大小写；包含空格时使用引号。需要查询 ID 时继续使用 `crop_helper_diag.lua catalog`。

终端输出使用 OpenOS 自带的 `less`，可用 ↑/↓、PageUp/PageDown、Home/End 查看，Q 退出。也可以将报告导出到文件：

```sh
crop_plan.lua inventory > /home/seed_inventory.txt
crop_plan.lua plan IC2:coffee 2 > /home/crop_plan.txt
```

## 种子识别与资源约束

- 完整分析的 IC2 种子袋通过 `stack.crop.name` 匹配服务器目录，并读取生长、产量、抗性；三围必须为 0～31 的整数。
- 多个槽位按品种合计数量，同时保留各槽位及三围。目录同名、分析信息缺失或数值无效时，列入未识别清单，不猜测身份，也不纳入路线资源。
- 非种子物品只统计占用槽位数，不取出、不清空。
- 每个品种保护一份。异种双亲本要求两种各至少两份；同种双亲本要求至少三份。资源不足会提示缺口，不能用唯一种子启动预演中的部署任务。
- 每一步按两份种子用于工作亲本扣除库存，不预估拆除亲本后能回收种子。同一组工作亲本批量收集本步骤的结果，然后才进入下一步。
- 中间品种默认先保存三份，供一份保种、两份工作使用；不套用最终三围筛选。最终目标数量按箱内种子总数理解，已有数量足够时无需继续杂交。

## 路线含义与当前边界

工具从服务器实时读取目录和规则指纹，在 OC 内计算条件权重。不会把仓库中的 `crop_catalog.txt` 当成可能过期的运行时数据库；该文件用于离线核对与测试。

采用有预算的束搜索，默认最多 4 步、每层保留 6 个状态、评估 256 次亲本组合。搜索会定期让出执行时间，避免长计算阻塞 OC。重复状态记录只保留入选分支，不建立全组合大表。

报告中的概率以两个亲本均已参与、忽略工位环境过滤为前提。路线排序分值按计划保存数量和条件概率累计，未计入亲本参与率、成熟耗时及取种失败率，不是预计秒数、保底次数或最优路线证明。未找到路线仅表示当前库存和搜索预算下没有找到，不能据此判定不可达。

本阶段只规划品种和数量；个体三围会展示，但不预测遗传结果。现场检查目前只验证当前位的杂交前置条件，不证明整条路线的环境、成熟和取种条件都满足。候选路线不能直接自动执行。

## 核对当前工位

盘点与多步预演已由用户实机验证。使用服务端 0.3.0 的 `site` 查询核对当前工位；更新上述 Lua 文件后运行：

```sh
crop_plan.lua check IC2:coffee 2
```

命令先盘点、规划，再将路线第一步的双亲本及中间品种与当前工位核对。不会部署亲本或清空中央位。亲本左右顺序可互换；当前亲本与首步不一致、中央已有作物或缺少双层架时，报告未通过。

若只想检查当前布局和亲本，可更新诊断脚本后运行 `crop_helper_diag.lua site`。该命令也需要 `/home/lib/crop_site.lua`。

报告分为通过、未通过、未知。当前支持经审核的 IC2 基础作物和 GT 通用作物类；未审核的特殊作物、版本不同或缺少所需环境信息时保持未知，不默认通过。候选还必须具有正权重。后续步骤尚未部署，必须在换亲本后重新检查，不能用首步报告代表整条链。

服务端 0.2.1 修复 GT 主模组版本为 `MC1710` 导致的误报未知；需要停服替换旧 JAR 并重启。同时更新 `/home/lib/crop_site.lua`，未知结果会显示具体原因。含空格的候选 ID 必须加引号，例如：

```sh
crop_helper_diag.lua site IC2:wheat IC2:wheat "gregtech:Brown Mushrooms"
```

此示例按现场左右均为小麦；其他亲本应替换为实际 ID，路线检查仍使用 `crop_plan.lua check IC2:coffee 2`。

工位检查只在服务端 tick 线程访问已加载位置，作物判断使用只读快照，不调用真实杂交。通过表示当前杂交前置条件满足，仍不授权自动种植、收获或丢弃。当前全部工位前置检查已实机通过。0.3.0 单次取种功能见下节；固定双亲本的完整循环见下节；自动换亲本与链式执行仍待实现。

## 固定亲本全自动循环

这是持续刷出指定品种的命令。沿用教程布局，无需手动清除每一轮失败结果或重启命令。服务端继续使用 `crop-helper-0.3.0.jar`，本次更新/新增三个文件：

| 操作 | 项目文件 | 机器人路径 |
|---|---|---|
| 更新 | `oc/crop_collect.lua` | `/home/crop_collect.lua` |
| 更新 | `oc/lib/crop_collect.lua` | `/home/lib/crop_collect.lua` |
| 新增 | `oc/lib/crop_auto.lua` | `/home/lib/crop_auto.lua` |

原有 `crop_preview.lua` 和 `crop_site.lua` 保留上一阶段版本。准备要求与单次取种相同：停止旧脚本，独占机器人及上方种子箱，清理附近旧掉落物，腾空非功能背包槽，至少留两个上方空槽并为副产物准备足够容量；1号槽只放作物架，15、16号槽原工具和除草剂保留。下方原补给容器放 IC2 作物架，脚本按物品身份选取，不会拿其他物品。维持供电和区块加载。

```sh
crop_collect.lua auto "gregtech:Brown Mushrooms" 2 5
```

参数依次为：

- 完整目标品种 ID（含空格必须加引号）。
- 上方箱内希望拥有的已分析目标种子**总数**，默认1，已有种子计入；不是新增数量。
- 扫描间隔秒，默认5，允许0.5～60秒。

运行流程：核对当前位置、两株亲本、额外邻居和目标正权重 → 补充/恢复中央双层作物架 → 等待结果 → 非目标立即拔除，目标等待可取种后拔除 → 确认种子身份及入库 → 回收掉落作物架到1号槽，其他副产物存上方箱 → 恢复杂交架继续。中央方块被打掉时会重新放置；仅剩单层时只升级一层。所有动作均核对实际结果，不只依据 API 返回值。

目标掉零种子会继续下一轮；掉落的非目标 IC2 种子袋也核对后保存，不直接扔掉。**非目标幼苗会立即清除，未成熟时可能完全不掉种子，新出现的非目标品种不保证能保住。** 本命令按当前固定双亲本刷目标品种；它不会替换左右亲本，也不会自动部署规划路线的下一步。目标本身的取种条件必须受0.3.0接口支持；未知时保留植株并停止。

每轮先清空已核对的掉落物，再允许下一次拔除，避免上一轮物品混入新批次。只有上方容器实际识别的目标种子数量达到要求，才完成任务；目标袋尚留背包中、身份未知或仅扫描到目标植株都不算成功。达标后停止，不再额外消耗作物架；中央位可能留下空架，属于任务结束后的正常现场。

```sh
crop_collect.lua auto_status
crop_collect.lua status
```

`auto_status` 查看持续任务、已处理轮数、上次确认库存和待核对动作；`status` 查看最近一轮取种批次。循环状态保存在脚本同目录 `crop_auto.journal`，单次批次仍为 `crop_collect.journal`。

按Ctrl+C停止。纯等待中断后，可用相同目标及数量重新执行 `auto`，程序核对原亲本、位置、机器人身份及规则后继续；已确认完成的补给等步骤也可以在满足背包/容器检查后继续。若记录停在 `*_pending` 或取种批次未完成，程序会阻止重放：先查看记录并人工核对装备、中央位、背包及相关箱槽，保存剩余物品，再归档未完成记录。箱满、补给不足、亲本/位置变化、未知种子、部分转移或动作结果不符均会停止并保留现场。不要直接删记录跳过核对。

## 单次中央取种验证

这是当前工位检查通过后的下一项实机验收。需要服务端 `crop-helper-0.3.0.jar`，并在已有预演文件之外安装：

```text
/home/crop_collect.lua         <- oc/crop_collect.lua
/home/lib/crop_collect.lua     <- oc/lib/crop_collect.lua
/home/lib/crop_preview.lua     <- 更新为当前版本
/home/lib/crop_site.lua        <- 更新为当前版本
```

1. 保持机器人在原中央待机位、面向中央作物。停止旧 `crop_hybridizer.lua`，测试期间独占机器人和上方容器，暂停该箱的漏斗、管道和其他程序，清理附近旧掉落物，避免混入本批次。中央自然出现其他品种时先保留现场，本命令不会清除它们。
2. 先运行 `crop_collect.lua inspect`。此命令只读，显示实际中央品种、阶段、三围及取种条件。中央还是空双层架时等待结果；未成熟时等待生长；未知时不执行取种。
3. 非功能槽全部腾空（至少16格背包，保留1、15、16号原功能槽）。上方容器至少留2个空槽。背包任何槽内已有种子都要先人工保存，避免混入本批次。
4. 中央确实出现 `gregtech:Brown Mushrooms` 且取种条件通过时执行：

   ```sh
   crop_collect.lua collect "gregtech:Brown Mushrooms"
   ```

   参数是**现在中央要拔除的品种**，不是尚未出现的最终目标咖啡。实际品种不符时停止。每次只拔除一株，使用空2号槽暂存手持物并空手左击，完成后恢复装备。只向上方箱子的预留空槽逐份转移本批次确认的种子袋，核对源槽减少、目标槽身份和数量增加，再记录成功。原有库存不计为本批次成果；副产物保留背包。
5. 查看 `crop_collect.lua status` 和上方箱子。预期为 `done` 且入库数与实际相符；`no_seed` 表示未检测到 IC2 种子袋，不计成功。种子掉落随机，成熟和条件通过不保证有种子。

首版取种支持当前审核过的 GT `GTBaseCrop`（含 `gregtech:Brown Mushrooms`），以及 IC2 咖啡、棕色蘑菇、小麦；小麦三围都不超过1时只出普通种子，拒绝作为 IC2 种子袋任务执行。其他作物继续返回未知，取种判断使用作物实际 `canBeHarvested()`，不以统一的 `size == maxSize` 代替。

单次命令结束即返回，**不等待下一株、不补架、不换亲本、不清背包、不推进整条路线**。检查并保存背包副产物、恢复中央双层架后，才可测试下一轮。首次得到的种子也有可能不掉落；本阶段不承诺无损保留唯一新品种活体。

动作前将批次状态追加到脚本同目录的 `crop_collect.journal`。断电、箱满、未知种子、种子身份不符或转移无法确认时会保留记录；未完成记录阻止再次拔除。本版采用故障后人工核对恢复，不自动重放：先运行 `status`，检查中央、装备、背包和记录中的上方箱槽，保存剩余种子并处理待核对转移，再将旧记录改名归档。不要通过删除记录来跳过未核对的动作。写入失败或记录损坏同样停止；完成记录保留作为入库回执。

## 自动等待目标并取种

无需反复手动运行 `inspect`。在上述单次取种准备完成后运行：

```sh
crop_collect.lua wait "gregtech:Brown Mushrooms"
```

可选第三个参数指定扫描间隔，默认5秒，允许0.5～60秒：

```sh
crop_collect.lua wait "gregtech:Brown Mushrooms" 2
```

空架期间先核对真实工位、该候选的条件和正权重，通过后定期扫描。目标出现后继续等待该株满足实际取种条件，再调用现有单次拔除、种子识别和入库核验流程。只在状态或生长阶段变化时输出，持续空架不会刷屏。整个命令收集一株后结束，零种子仍按 `no_seed` 处理；不自动重试拔除。测试期间维持供电并保持工位所在区块加载。

按 `Ctrl+C` 可停止。等待阶段只读，不写拔除意图；实际取种开始后沿用原有批次记录和故障保护。未完成记录、背包未腾空或上方不足2个空槽，会在开始等待前提示。进入取种前还会重新核对位置、亲本与目标身份；等待中的目标消失、三围变化、出现未知条件或其他品种时保留现场并停止。`wait` 仍是保守的单次等待命令；需要自动清除非目标并持续补架时，使用上面的 `auto`。

仅使用 `wait` 时需要 `/home/crop_collect.lua` 和 `/home/lib/crop_collect.lua`；持续循环 `auto` 还需要新增 `/home/lib/crop_auto.lua`。辅助模组继续使用0.3.0，无需更换 JAR。
